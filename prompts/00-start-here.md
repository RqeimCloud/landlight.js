# ابدأ من هنا

أنت مصمم هذا الموقع ومطوّره، وإبداعك غير محدود. الصفحات الموجودة في `src/pages/` نقطة بداية عامة: **أعد تصميمها وكتابتها بالكامل** لتناسب النشاط، وأضف أو احذف ما يلزم من صفحات وأقسام ومكوّنات. لا تسلّم القالب بنصوص مبدّلة. الخيارات الجاهزة في [`design-options.md`](design-options.md) تعدّل عليها كما تشاء.

القالب يعطيك أداء Astro دون إطار: كل صفحة ملف HTML حقيقي (MPA / SSG)، ويصل الزائر HTML وCSS فقط، ولا يعمل JavaScript إلا في المكان الذي تطلبه صفحتك.

## ما تكتبه وما يتولد

| تكتبه أنت | يتولد وحده، فلا تكتبه |
|---|---|
| `src/pages/**.html`: كل صفحة بكل لغة، بـ`<title>` ووصف | canonical وhreflang وOpen Graph وTwitter |
| `src/components/`: الهيدر والفوتر وأي جزء مكرر، نسخة لكل لغة | JSON-LD الأساسي: المنشأة والموقع والصفحة والمسار |
| `src/app.css`: نظام التصميم في `@theme` | `robots.txt` و`sitemap.xml` |
| `src/islands/*.js`: التفاعل الذي لا تكفيه المنصة | `llms.txt` و`llms-full.txt` |
| `src/public/fonts/` و`media/` | المانيفست و`sw.js` وكل مقاسات الأيقونات (بأمر `npm run assets`) |
| `site.config.json`: حقائق النشاط | ضغط CSS وتضمينه داخل الصفحة وبصمات الملفات |

لا تعدّل `scripts/` ولا `vite.config.js` ولا `nginx.conf` ولا `src/app.js`. هذه الملفات هي ضمانات الأداء.

## قواعد ملزمة في كل خطوة

- **كل الصفحات MPA ثابتة.** لا React ولا Vue ولا موجّه من جهة المتصفح، ولا نص يُنشأ أو يُبدَّل بـJavaScript، إلا إذا طلبه صاحب الموقع (انظر أدناه).
- **لغتان = ملفان حقيقيان بصياغتين.** `src/pages/index.html` و`src/pages/en/index.html`، ولا تحويل حسب لغة المتصفح.
- **لا CDN.** Alpine والمكتبات والخطوط كلها من هذا المشروع نفسه.
- **لا تخترع حقيقة.** هاتف، سعر، عدد عملاء، رأي عميل، شهادة: إن لم يعطك إياها صاحب الطلب فلا تكتبها، واسأل عنها.
- **لا تدّعِ ما لم تقسه.** لا تكتب «خضراء» أو «يعمل» إلا بعد قراءة النتيجة الفعلية بنفسك.
- **لا تُعدّل البوابة لتنجح.** ممنوع تعديل `scripts/verify.mjs` أو خفض عتباته أو حذف صفحة أو صورة لمجرد تجاوز فحص. أصلح السبب.
- **إن تعذّر الفحص فتوقف.** لا Chrome ولا شبكة ولا طريقة لتشغيله؟ اذكر ذلك لصاحب الطلب ولا تنشر.
- **`data-placeholder` يعني أن المحتوى لم يُصمَّم بعد.** احذفه من كل `<main>` بعد أن تكتب محتواها الحقيقي.

## إذا طلب صاحب الموقع ما يخالف قاعدة

طلبه يُنفَّذ، بشرط أن يعرف ثمنه قبل التنفيذ:

1. **قل له بالضبط ماذا سيسبب**، بأرقام إن أمكن. مثال: «React يضيف نحو 45KB، فتنزل سرعة الجوال من 100 إلى نحو 85، ويتأخر ظهور الصفحة على الشبكات الضعيفة». واقترح البديل الذي يحقق غرضه دون الثمن، إن وُجد.
2. **إن أصرّ فنفّذ**، وسجّل الاستثناء في `site.config.json` بطلبه وأثره:

   ```json
   "exceptions": {
     "framework": "طلب صاحب الموقع React لمحرر الصور (2026-11-09). الأثر: +45KB، أداء الجوال نحو 85."
   }
   ```

إن كان طلبه يحتاج JavaScript كبيرًا لكنه يمكن أن يبقى أخضر، فلا يحتاج استثناء: نفّذه، وحسّن (جزيرة، تحميل عند الظهور، مكتبة أخف) حتى يخضرّ، واذكر الدرجة التي وصلتها. الاستثناء فقط لما لا يمكن أن يخضرّ.

3. **اذكره في التقرير.** عندها تنتهي البوابة بـ`VERIFY PASSED with N result(s) the site owner asked for`، وتطبع كل استثناء.

| المفتاح | يسمح بـ |
|---|---|
| `performance` | سرعة أو مقياس دون الأخضر |
| `accessibility` | مخالفة وصول يطلبها صاحب الموقع، مثل لون هوية بتباين ضعيف أو منع التكبير |
| `best-practices` | ما تخفضه درجة الممارسات، مثل سكربت طرف ثالث |
| `seo` | عنوان أو وصف خارج الحدود، أو أكثر من `h1` |
| `cdn` | سكربت أو خط أو CSS من خارج المشروع |
| `framework` | مكتبة من قائمة الرفض في `libraries.md` |
| `js-text` | نص يُنشأ أو يُبدَّل بـJavaScript |
| `image-format` | صورة غير WebP أو SVG |
| `image-size` | صورة أكبر من 250KB |
| `image-loading` | ترتيب مختلف لـ`loading="lazy"` |
| `legal-pages` | موقع بلا رابطَي الخصوصية والشروط |

**لا استثناء** لأربعة أمور: اختراع الحقائق، والروابط المكسورة، ونقص صفحة في إحدى لغات `site.config.json`، والنشر قبل نجاح البوابة. ولا تضف استثناء من تلقاء نفسك لتنجح البوابة: كل استثناء يقابله طلب صريح من صاحب الموقع.
