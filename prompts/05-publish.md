# 5. انشر وتحقق من الموقع الحي

## قبل الدفع

- [ ] آخر `npm run verify` انتهى بـ`VERIFY PASSED`، ولم يتغير أي ملف بعده. أي تعديل، ولو سطرًا، يوجب إعادته.
- [ ] راجعت الجوال على 375px بنفسك.
- [ ] جرّبت كل نموذج أو زر تواصل فعليًا.
- [ ] صاحب الطلب أذن بالنشر.

## النشر

ادفع إلى الفرع الافتراضي، فيُبنى الموقع وينشر تلقائيًا. انتظر حتى يكتمل النشر قبل الخطوة التالية.

## بعد النشر

```bash
npm run verify -- https://الدومين-النهائي
```

هذا يفحص الموقع الحي نفسه: `robots.txt` و`sitemap.xml` و`llms.txt` وملفات PWA، وأن `sw.js` لا يُخزَّن فلا يتعطل التحديث، وأن الصفحة المفقودة ترد 404 حقيقية، وأن كل canonical يشير لنفسه، ثم Lighthouse لكل صفحة في خريطة الموقع.

إن فشل: أصلح، وأعد الخطوات من `04-verify.md`، ثم انشر مجددًا.

## محركات البحث

- شغّل `npm run indexnow` بعد كل نشر فيه تغيير محتوى، ليصل التحديث إلى محركات IndexNow (ومنها Bing الذي تعتمد عليه بعض مساعدات الذكاء الاصطناعي).
- أرسل `https://الدومين/sitemap.xml` في Google Search Console وBing Webmaster Tools إن كان لديك وصول إليهما.
- لنشاط له مقر: اطلب من صاحبه إنشاء ملف Google التجاري بالاسم والعنوان والهاتف نفسها.
- إثبات ملكية الدومين يحتاج سجل TXT من صاحب الموقع. اطلب منه القيمة، ولا تدّعِ إتمامه.
- `llms.txt` يتولد مع كل بناء. عند تغيير المحتوى لاحقًا أعد النشر ثم أعد إرسال خريطة الموقع.

## التقرير

أرسل لصاحب الطلب بهذا الشكل، بأرقام من الناتج الفعلي:

```
الرابط: https://...
البوابة قبل النشر: VERIFY PASSED
الموقع الحي: VERIFY PASSED
استثناءات بطلبك: (كل استثناء وأثره، أو «لا شيء»)

الصفحة | الجهاز | أداء | وصول | ممارسات | SEO | LCP | CLS | TBT
...

راجعته يدويًا: الجوال 375px، أزرار التواصل
ما يحتاج منك: (مراجعة النص القانوني، قيمة TXT لإثبات الملكية، أي نقص)
```
